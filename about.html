Background & Mission

Engineering with Empathy, Rigor & Universal Access

I am a Senior Software Engineer and Digital Accessibility Architect with over eight years of experience steering web applications from nascent prototypes to globally recognized, accessible enterprise platforms.

My engineering philosophy revolves around a simple truth: the web is fundamentally meant to be universal. When we compromise on semantic HTML, omit proper ARIA roles, or neglect keyboard navigability, we exclude millions of users with motor, cognitive, visual, or situational impairments.

I specialize in bridging the gap between design tokens, engineering infrastructure, and legal compliance (ADA Title III, Section 508, European Accessibility Act). By establishing automated linting in CI/CD, authoring accessible component libraries, and conducting screen reader usability studies, I empower engineering organizations to produce resilient software without sacrificing aesthetic excellence.

Architectural Framework

The Four POUR Pillars in Production

How WCAG principles translate into concrete, production-grade engineering decisions.

1. Perceivable

Information and user interface components must be presentable to users in ways they can perceive. We implement text alternatives for non-text content, adaptable responsive layouts, and contrast ratios exceeding 7:1 for AAA certification.

2. Operable

UI components and navigation must be operable via any input method. All actions are reachable with Tab and Shift+Tab, skip links bypass repetitive navigation, focus traps are prevented, and animations strictly honor prefers-reduced-motion.

3. Understandable

Information and the operation of user interface must be predictable and intuitive. Forms use explicit <label for> association, live error validation linked via aria-describedby, and predictable focus placement upon submission.

4. Robust

Content must be robust enough that it can be interpreted reliably by a wide variety of user agents, including assistive technologies. We rely strictly on semantic HTML5 tags first, layering ARIA only when custom interactivity mandates it.
