Case Study: Enterprise Accessible Design Tokens & Linting

An in-depth breakdown of how we eliminated accessibility regressions at scale across 40 disparate engineering squads.

1. The Engineering Challenge

An enterprise financial organization was releasing UI updates that broke keyboard navigation and color contrast ratios, incurring legal vulnerability under ADA Title III and frustrating visually impaired customers. Over 1,200 non-compliant components existed in production across separate micro-frontends.

2. The Architectural Solution

We constructed the Aura Design System from the ground up:

  • Tokenized WCAG AAA Palettes: Strict contrast mathematical checks built into Style Dictionary design tokens ensuring any background/foreground combination guarantees 7:1+ contrast.
  • Headless APG Primitives: Modal dialogs with programmatic focus trapping, native <dialog> element adoption, and accessible live regions for dynamic alerts.
  • Automated CI Enforcement: Headless axe-core and Lighthouse CI integrated into Git pull request gates, blocking any merge that introduced an accessibility regression.

Sample Automated CI Rule (GitHub Action / axe-core) 

// Playwright + axe-core accessibility integration test
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

test('page must have 0 WCAG 2.2 AA/AAA violations', async ({ page }) => {
  await page.goto('/dashboard');
  const accessibilityScanResults = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa', 'wcag21aa', 'wcag22aa', 'best-practice'])
    .analyze();

  expect(accessibilityScanResults.violations).toEqual([]);
});
